## 📋 Field 4: Short Text Description of Your Work
```text
For this Capstone Project, I designed and developed an enterprise-grade, high-throughput batch image processing pipeline in CUDA C++17, specifically addressing latency and bandwidth bottlenecks when processing large volumes of visual data.

Key Architectural Innovations & Algorithmic Highlights:
1. Multi-Stream Asynchronous Pipeline (src/pipeline.cu):
The engine implements a 4-way concurrent stream scheduler (cudaStream_t). By dividing image batches across streams, the host overlaps PCIe Host-to-Device (H2D) transfers, multi-stage kernel compute, and Device-to-Host (D2H) memory writebacks, completely hiding memory transfer latency behind GPU execution.

2. Shared Memory Stencil Tiling with Halo Exchange (src/cuda_kernels.cu):
Both the 3x3 Gaussian smoothing filter and the 3x3 Sobel spatial derivative kernels utilize on-chip __shared__ memory. Each 16x16 thread block loads an 18x18 tile including boundary halo pixels with cooperative thread loading and boundary clamping. This eliminates redundant global DRAM transactions for adjacent stencil neighbors, achieving near-peak arithmetic throughput.

3. Complete 4-Stage Image Processing Graph:
Stage 1: Perceptual luminance calculation (ITU-R BT.601) converting 24-bit RGB to 8-bit grayscale.
Stage 2: 2D Gaussian blur for high-frequency noise attenuation.
Stage 3: Sobel gradient operator computing horizontal (Gx) and vertical (Gy) spatial derivatives and overall gradient magnitude: G = sqrt(Gx^2 + Gy^2).
Stage 4: Contrast normalization and dynamic thresholding producing binarized edge maps.

4. Standards & Code Quality:
The project strictly conforms to the Google C++ Style Guide, features zero memory leaks (RAII and explicit device memory deallocations), supports flexible CLI configuration (--input-dir, --output-dir, --streams, --threshold), and includes an automated Makefile and run.sh script.
```

### Part 2: System Architecture & Data Flow (1:30 - 3:00)
> "Let's examine the pipeline architecture shown in the README.md.
> The pipeline processes 120 full-color images. Rather than processing images sequentially on a single stream, which leaves the GPU idle during host-device memory transfers, I designed an asynchronous multi-stream execution engine.
> We allocate 4 independent CUDA streams. Each stream handles an image through an interleaved pipeline:
> - First, an asynchronous memory copy transfers the RGB payload to device memory.
> - Next, a sequence of four specialized GPU kernels executes.
> - Finally, an asynchronous transfer retrieves the edge map back to host memory while subsequent streams are already executing kernels.
> This overlapping of memory transfers and computation maximizes GPU hardware utilization."

### Part 3: Deep Dive into the CUDA Kernels (3:00 - 5:00)
> "Looking at `src/cuda_kernels.cu`:
> Stage 1 converts 24-bit RGB to 8-bit Grayscale using ITU-R BT.601 perceptual luminance weights.
> Stage 2 applies a 3x3 Gaussian blur filter to attenuate noise.
> Stage 3 applies the 3x3 Sobel operator to calculate horizontal and vertical spatial derivatives.
> A critical optimization here is Shared Memory Tiling with Halo Exchange. For a 16x16 thread block, we allocate an 18x18 `__shared__` memory array. The threads cooperatively load the interior pixels as well as the 1-pixel boundary halo. After a `__syncthreads()` barrier, every thread computes the convolution directly from high-speed on-chip cache without hitting global DRAM. This dramatically reduces memory traffic.
> Stage 4 performs dynamic threshold binarization to produce high-contrast edge maps."
